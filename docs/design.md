# LastPeek design

LastPeek is the quiet moment before posting on X. Minimal does not mean unfinished. Make the interface precise, distinctive, and obvious without explaining it away.

## Review overhaul trial

The current review overhaul supersedes the flat-feedback, All/Open/Resolved and blanket
“Earlier feedback” descriptions in the baseline below. Keep the theme-aware coral identity,
native post presentation, shared controls and responsive shell.

- Guest reviews now reuse the same desktop rail and mobile shell, with no guest topbar or footer.
  This supersedes the guest layout and name-on-send guidance below. On first opening, a shared
  Dialog offers a name, Continue as guest, Sign in and Request an account. Remember the name for
  the browser session. Guest navigation and the page's back arrow open a compact account prompt
  without changing the route or discarding feedback. Never trap external browser navigation.
  Sign-in opens separately so the draft and unsent comment stay in place. Guest avatars use
  Phosphor's dashed user circle; comments retain the entered name and a small Guest label.
  Account requests remain invite-only and appear in the owner's Invitations queue.
- One Discussion beside the draft on desktop and after it in mobile page flow. Authors can ask
  before sharing and reply in the same space as reviewers. Replies attach to the exact selected
  message at any depth. Normal back-and-forth continues flat within its tier; replying to an earlier
  message branches. View replies opens deeper branches with Back navigation and only one visible
  indent, preserving reading width on mobile. Compose after existing replies, where the new message
  will appear. Name and Author/Guest
  pills occupy the first line beside the 40px avatar; handle, time and compact Edited marker occupy the second.
  Comment content uses the full width below that identity header. Replies retain an indented connector.
  People can edit/delete their own messages. Guests use an HttpOnly browser-session credential,
  never their name, to establish ownership; their own messages say Guest · You. Non-leaf deletions
  retain an anonymous Message deleted placeholder; leaf messages and empty placeholders disappear.
  Reply composition stays inside its conversation with an inset send icon, no cancel cross. The general
  composer remains in place and retains its text. Guests provide a name only when sending.
- Draft and All Drafts share the same 1000px desktop application frame, including the 68px rail.
  The home feed retains its 600px main column. Post pages default to a 600px post and 24px gap;
  only their inner split is adjustable with a pointer or arrow keys (460–628px post width), saved on that device. The page has
  one document scroll, never an independently scrolling, viewport-height discussion sidebar.
  Only Discussion/AI review tabs stick during scrolling; sharing and destructive actions scroll away.
  Tabs have breathing room beneath the action strip. Private AI results stay
  mounted when switching tabs; changing tabs must not discard a comment or a finding.
- Authors and reviewers share an auto-growing composer without a redundant self-avatar. The compact comment action
  sits inside the field at the right. Enter sends, Shift+Enter adds a line, and composing IME input never sends.
  Three 44px quick-message pills animate below the focused general composer in one horizontally
  scrollable row without replacing unsent text or losing focus on touch. Selected wording and media use removable
  context chips. Friendship actions sit in the comment action row so identity metadata stays compact.
- Post/text/attachment context sits above the comment. Video feedback captures the current
  playhead without obstructing native controls. Context never silently migrates after an edit:
  Text changed, Post edited, Post removed, Attachment removed or Source changed opens a limited
  original/current comparison from the compact Edited marker. General comments show the same marker with a descriptive accessible label and tooltip, not a separate sentence.
- Authors can resolve conversations, which fade out of the active discussion. A quiet bottom
  separator opens resolved conversations; the empty separator says Nothing resolved. A new reply
  reopens them. Discussion counts exclude resolved conversations and their replies.
- Discussion belongs to its draft, not a separate navigation destination. Recent feedback and
  notifications link directly to the draft/comment; old `/feedback` bookmarks return to Drafts.
- Other viewers appear as a compact avatar stack beside the Post heading, with hover names and
  explicit guest identities and online dots. Hover or tap expands a name beside its avatar; mobile taps collapse again after a short delay. Entering/leaving viewers animate quietly. Mobile draft/review pages
  omit the separate account/mascot header; keep the post heading and bottom navigation.
- AI is private, not chat: one-click Quick review, Proofread, Clarity, Tighten, Tone and Thread
  flow stay above saved newest-first results. Findings offer Apply (when safe) and Dismiss, never
  Share to discussion. A lock beside the tab explains text-only provider/privacy/allowance details
  on hover. Each saved run has a menu to delete that private review without changing the draft.
  No automatic edits or public AI comments. Changed drafts disable stale actions.
- More draft actions contains Change draft type, using shared Select, with a source field for Reply/Quote.
  Errors stay inside the change dialog; writing, media and discussion remain intact.
- Desktop exposes Mark as posted and Delete beside sharing; mobile keeps them in More. No duplicate
  AI action above its tab. Images open a shared large Dialog; video enlargement sits below playback
  controls. Downloads live in the viewer, not repeated under posts. Image removal uses circular
  controls; video removal never overlays sound controls.

AI preset prompts follow [OpenAI’s prompting guidance](https://platform.openai.com/docs/guides/prompt-engineering)
on specific task boundaries, instruction/input separation and representative evaluation, and
[RISD’s editorial guidance](https://artsandlanguage.risd.edu/ai-literacy-grammarly-tips) on preserving
meaning, voice and quotations. Proofread corrects errors, not style; clarity names ambiguity rather
than inventing context; tightening retains meaningful qualifiers; tone describes plausible reader
interpretations, not the author's emotions; flow examines actual transitions. All modes avoid
flattery, forced criticism, new facts and engagement bait. Prompt changes do not guarantee model
quality; evaluate representative clean, faulty and subjective drafts when iterating.

## Identity

- Settings → Personalisation offers Auto, Dark and Light. Auto is the default and follows OS changes immediately. Save the choice to the account; retain a cosmetic browser cookie for signed-out and offline pages. Server-render the preference before paint rather than flashing a different theme or weakening CSP for a boot script. Explicit changes cross-fade the page over 240ms using native view transitions; reduced motion and browsers without that API switch immediately. Never animate initial rendering or move the layout when changing appearance.
- Light uses the product film's warm cream (`#fff6ed`), ink (`#22191b`), ivory surfaces and soft warm borders. Dark retains its near-black page (`#0b0b0c`), raised surfaces (`#161618`), hairline borders (`#2b2b2e`) and warm off-white text (`#f2f0ec`). Define both sides together with `light-dark()` semantic tokens in `src/app.css`; shared controls, post previews, feedback, menus and errors inherit them. Do not add page-specific theme overrides or fixed dark canvas/text colours. Actual photos/video canvases, scrims and the mascot's eyes retain their intentional colours.
- Coral (`#ff6b5b`) belongs to LastPeek: the logo, primary actions, focus, and shared state. Use it sparingly. Light-mode filled controls and active navigation icons use brighter coral (`--primary-fill`, `#e05c4b`), with ink text on filled controls. Small coral text and links retain deeper `--primary` (`#b94032`) for contrast; the logo keeps the original coral. Dark-mode fills remain `#ff6b5b`. Destructive states use theme-aware rose so they never read as a primary action. No decorative gradients, rainbow statuses, or glowing dashboard chrome.
- The mark is a coral speech bubble with two off-white eyes glancing right; the wordmark is “LastPeek” outlined from Outfit (OFL), with ordinary e’s, never eyes in the typography. Both live as SVG in `Brand.svelte`, so no font is loaded. The mascot pupils follow a nearby mouse and rest looking right; the motion is decorative, so it stays still for touch and reduced motion. Keep `static/favicon.svg`, `favicon.ico` and `apple-touch-icon.png` in sync with the mark; do not replace it with a generic library eye.
- Use system Arial/Helvetica for an X-like, local-first type stack. Clear hierarchy, quiet metadata, comfortable contrast. No required remote fonts or image services.
- Signed-in pages use a centered application frame with a 68px fixed left navigation rail attached to the content, not the viewport edge: the mark alone at the top, Drafts and Feedback beneath it, and the account avatar at the bottom. The avatar opens settings and has visible hover, keyboard-focus and current-page treatments. Mobile places the account at the top left and mascot centered in a 52px row with tabs below. Page-specific search is the first item in the scrolling feed, not fixed chrome. Drafts/Feedback sit in a compact 48px bottom row with a reduced safe-area inset that still clears the home indicator and retains 44px touch targets. Admin has no visible navigation button: retain the desktop `~` shortcut and a mobile mascot long-press gesture for authorized admins. The header, tabs, bottom navigation and floating plus follow one clamped scroll offset without fading or direction thresholds; reverse immediately with the scroll and settle gently only after scrolling ends. Clamp iOS rubber-banding so it cannot spuriously reveal the bars. Transform fixed overlays rather than moving content, and keep the top safe-area background stationary. The floating plus remains visible as it lowers with navigation; it includes enabled quote/reply options. Signed-in pages have no footer. Signed-out and guest-review layouts keep their existing headers and footer.
- The rail's mascot reacts through its eyes, never by moving, tilting or scaling the logo. On hover-capable pointers, a quick blink opens into tall, wide eyes with small pupils for a surprised double take. Finish the reaction even if the pointer leaves early, then ease back to rest; re-entering during the reaction must not restart it. There is no hover background. Mobile mascot taps trigger the same reaction and scroll to the top; ambient pointer-following stays off for touch. Respect reduced motion for all reactions and navigation transitions. Navigation icons are filled on their active page and outlined elsewhere, with a subtle circular background that fades in only on hover.

## Components are the source of truth

- Use the checked-in shadcn-svelte (Vega) controls under `src/lib/components/ui`: Button (also for action links), Input, Textarea, Checkbox, Badge, Tabs, Dialog and Alert Dialog. Use Checkbox for every checkbox, including form submission, disabled and indeterminate states. Use the shared `ConfirmDialog` for destructive draft, post, friendship and notification actions, and audience changes; never browser alerts. Preserve browser-managed unsaved-navigation warnings. Tailwind 4 and semantic CSS variables in `src/app.css` supply the theme. Change a shared control for a shared visual rule; do not create competing page-local buttons or form fields.
- Components are owned source, customized for LastPeek, not a runtime hosted service. Additional components should come from shadcn-svelte and be added only when needed. The CLI currently cannot resolve Kit 3's `$app/tsconfig`; components can be copied from the official registry (`https://www.shadcn-svelte.com/registry/styles/vega/<name>.json`), replacing its utility/UI aliases with this repository's aliases. Do not downgrade Kit or rewrite its TypeScript setup to accommodate the CLI.
- Use Phosphor (`phosphor-svelte`), regular weight, through `Icon.svelte`. Import individual `phosphor-svelte/lib/<Name>` modules so builds do not compile the entire icon library. Custom SVG is for the brand, not a second icon family.
- Use component variants rather than legacy `primary`/`quiet` classes. Layout classes describe real surfaces and relationships; don't create one-off control themes. Use the prepared shared Select, not native selects. File input and progress semantics remain valid; review context uses shared Dialog rather than disclosure accordions. Preserve keyboard and touch usability.

## The post is the product

- `PostPreview.svelte` renders posts for both authors and reviewers. Do not fork their preview styling. A desktop timeline is at most 600px wide; mobile uses available width without shrinking text or removing capabilities.
- Home uses Drafts / To review / Done queues with Phosphor NotePencil, ChatCircleDots and CheckCircle icons. The two active queues have quiet counts. Drafts is the default; Done combines posted drafts and up-to-date reviews with Posted/Reviewed labels. Preserve the selected queue through refresh and return navigation. Put Mark as posted inside More draft actions, directly above Delete draft; posted drafts cannot move back. After marking, stay in the editor to link the published post. A confirmed link replaces publishing with View on X. A possible match offers Is this it? linking to X, with a down-arrow menu for Yes, that’s it / No, another post. Missing or rejected matches offer Paste post link, with inline manual entry if clipboard access fails. Reviewers use one Send feedback split button, with a right-hand down arrow offering “Looks good!” as ordinary general feedback; disable that shortcut while unsent text exists rather than discarding it. Sending current-revision feedback clears the review; author edits bring it back. No separate Finish review, Reopen review or Request another look controls. Cleared active queues say “All clear.” without a success banner. Videos use muted inline autoplay with native controls in both feed and detail, without making video controls open the draft.
- The drafts page starts with 44px-high icon-and-label filter tabs, without a heading, total or sort control; drafts stay in last-updated order. On wide screens, the first draft follows the tabs directly. Search with a magnifier, a full-width sticky New post split button, and the five latest unresolved comments occupy the right column, in that order. Keep enabled quote/reply options together with New post. Drafts search covers all post text, not comments. The Feedback page searches feedback bodies, reviewer names, quotes and legacy suggestions, with All/Open/Resolved filters and links to each original feedback card. Earlier feedback stays labelled. On desktop its right sidebar shows recent drafts. Below 1000px, search and creation follow the tabs; below 600px use the mobile shell and floating creation button, with no feedback appended to the drafts feed. Empty results use the original mascot as a decorative character, “Not a peep.” and brief helpful copy with generous spacing before the reset button; no nested border or dashed card.
- X-like post text, muted handles, blue links, 40px avatars, 12px avatar/content gap, and 15px/20px text anchor both the writable post and the review. Post colours follow the selected appearance through the shared post tokens. Preserve actual whitespace and Unicode. URLs, mentions, and hashtags are highlighted while editing and linked in read-only views, without rendering user-supplied HTML.
- Draft-list posts and empty states blend into the page canvas, separated by hairline borders rather than raised backgrounds. Show the current name, handle and actual last-updated time together. Thread length, unresolved feedback count (including zero), and sharing state form one quiet grey icon row; blue, pink and green hover/focus accents and labels identify each action without inventing social engagement. Feedback links jump to the editor's feedback. Recent guest feedback uses name-initial avatars. Only after scrolling, and only when the draft list itself extends below the initial viewport, finish it with Back to top and a secondary New post split button, including enabled quote/reply options. No end-of-list heading or subtext. Empty search results offer both reset and creation. Empty-state mascots share the rail's eye reaction and reduced-motion/touch rules.
- A preview is a timeline post, not a marketing card. Media has rounded, bordered crops and tight multi-image grids. Threads have continuous connectors. Do not invent timestamps, verification, follower counts, engagement, or controls for unsupported X features.
- Edit directly in the post layout, with no title, per-draft identity fields, or Write/Preview switch. The account avatar opens settings; the logo goes home. Editing controls and character counts disappear in reviewer and historical views. Use `twitter-text` weighted counts, including URLs and Unicode, not string length. Long drafts stay supported; Premium requirements are contextual, not an always-visible paragraph.
- Like X's composer, only the post being written shows its tools: coral Phosphor icons for upload, copy text and download, the count ring, and a compact outlined plus that inserts the next post after it. Other posts in the thread dim until focused; the active post's header has a small remove control. Empty posts disappear immediately; text or media requires an in-page confirmation with Keep post and Remove post. Posts are not reordered. In reviewer and historical views, copy and download icons sit along the bottom of every post. Links inside posts stay X blue; LastPeek's own controls use coral. Do not copy whole threads. Don't label an action “Post” if it only copies text. Pro authors get a labelled coral Post to X button to the right of the final plus, not in the feedback/sharing strip, when X publishing is configured. Use the X logo in place of the final X character, not as an additional leading icon; likewise for View on X and Connect X. Multiple-post drafts say Post all. Keep this final toolbar visible for participating authors. Click confirms the connected account in a compact native dialog with a hold-to-skip tip, not a duplicate post preview or sound checkbox. A deliberate 1.5-second hold compresses the button, fills a warm gradient with a travelling sheen and glow, and builds a tuned sound with accelerating haptic detents. Success resolves with a short chord, spring and sparks. Cancel aborted gestures, respect reduced motion and keep errors local; do not add idle helper text below the control. Media preparation/upload/processing updates the button label. Partial threads offer Continue posting with the published count, an X link and confirmation that only the remaining posts will be sent. View on X replaces the button only after complete confirmed success, with changed-since-posting context in its title. At narrow widths the publishing group may wrap below media tools, but plus and Post to X remain together.
- Individual drafts reuse the drafts feed's 600px main column, 24px gap and remaining sidebar width. The post blends into the page canvas, without an outer rounded card. A back arrow and Post/Comment/Quote heading orient the page; a quiet pencil Edit shortcut focuses the always-editable text without adding a coloured edge. A single sidebar action strip groups sharing, the optional AI Review sparkle icon, and a more-actions menu containing deletion with confirmation. Icon actions retain accessible names and titles. Sharing becomes a Copy link split button with only Remove link in its dropdown; no separate Open preview action. Buttons transition colours and focus treatment consistently without moving on click, and sharing leaves its loading state before switching to Copy link. Flat human feedback follows a divider, without a redundant heading or refresh icon; resolved comments stay readable rather than dimming the whole item. Below 1000px, actions precede the editor and feedback follows it. Keep successful autosaves quiet; show failures inline and warn before leaving unsaved edits. Signed-in reviewers use the same app shell as their drafts: desktop rail, account avatar, mobile header and bottom navigation, without a guest topbar or footer. Signed-out visitors retain the topbar and footer, which rests at the viewport bottom on short pages and follows content on longer pages. Account-linked feedback uses current names and photos everywhere; guest and legacy feedback keep their supplied name and initial.
- Account Profile contains the user's display name and photo, without an introductory caption. Use a small top-right remove cross on the photo; place the name beside it on roomy desktop widths and below it on mobile. The handle comes automatically from the connected X account, with no editable field or import toggle. Avatars are private, cropped to a square and compressed; header and posts use the same profile photo, while historical versions retain theirs. All Settings headings have a 16px content gap. Notifications retains its brief introduction and compact preference rows, current-device control and other enabled browsers, with registration dates rather than online claims.
- Settings keeps its sidebar and detail pane on desktop. On mobile, `/settings` is a vertical icon-and-label navigation page; opening a section replaces the list with its content. Show back controls beside Settings and section headings only on mobile, and use an outlined Sign out button. Do not show the app's avatar/mascot header or horizontal section tabs on mobile Settings; retain the main bottom navigation. Direct section links, browser history and native forms must work. Allowances puts its plan badge beside the heading and separates saved draft/media capacity from Pro's monthly AI/X usage, with restrained coral meters and the X logo. Show used/limit counts for saved capacity, but percentage used for AI and X, never dollar amounts. A zero API allowance says No allowance rather than a misleading percentage. Show the monthly period's start and end dates in UTC as plain text, not a dropdown or a billing claim; omit the per-upload limit. Free has saved capacity only. Keep actual scheduled plan/allowance changes as quiet text and capacity errors beside the affected meter.

Settings → Security replaces Password with one combined page. Flat signed-in browser rows come first, with a quiet This session badge, browser/platform hints and recorded activity. Other rows have 44px Sign out controls; a rose Sign out other sessions action appears only when needed. Both actions use the shared confirmation dialog, retain the current session and remove revoked rows without a success notice. Password fields follow a divider. Mobile keeps all controls in the same order. Agent permissions remain in Agents, not in the browser-session inventory.

Review sessions, signed in or not, reuse the draft editor's flat post presentation, back arrow, Post/Comment/Quote heading, 600px main column and 24px sidebar gap. The sidebar holds the feedback form and flat feedback list instead of author actions. On narrow screens the form and feedback follow the post. Signed-in back navigation returns to Drafts; guests return to their previous page, with sign-in as the fallback for a directly opened link. Review posts remain read-only and never expose Edit, sharing or deletion controls.

## Copy and interaction

- Friends is the third rail/bottom-navigation destination, with a numeric incoming-request badge. Friends occupy a 600px main column; incoming/sent requests and Add by email occupy the sidebar. On narrow screens, requests appear first in a native collapsible disclosure. Use `UserIdentity` for live account display across friends, feedback, notifications, sharing, navigation, consent and admin: a shared 40px photo/initial and a single-line name and optional muted handle. Only accepted friends can see peer activity: a restrained green avatar dot for recent activity, with “Active now” or “Last seen … ago” in detailed identities. Notifications and feedback use compact identities with the dot but no activity text; event/comment timestamps remain. Feedback places a small Add friend text action beside the timestamp, not beside Resolve, retaining a 44px touch target. Outgoing requests say Request sent (click to cancel); incoming requests offer Accept request; accepted friends and self show no extra action. Name-only guests never imply an account or expose activity/actions. Actions and errors stay outside the feedback card's navigation link; no nested controls or hover-only actions. Navigation uses the avatar-only variant; admin retains its separate privileged activity column. Keep names and handles available at narrow widths with ellipsis, not page-local hiding. Post snapshots and external X identities remain separate. No “wants to be friends” caption or shared-review inbox. Notifications is a separate bell destination with an unread count, event history, mark-read actions and a Settings link; show the sender identity instead of a generic event icon, without inline friend controls. Add by exact email, or use Add friend beside account-linked review identities. Sharing first offers Friends only and Review link as distinct audiences; recipient rows show Send or Remove access. Changing audience confirms the access consequence. Existing public links keep the Copy link split control, with Share with friends and Remove link in its menu. Do not imply that bearer links authenticate recipients or that recent activity guarantees someone is online.

- Below 600px, Friends and Notifications replace the centered header mascot with their page heading, keeping the account avatar at left. Notifications has no outer vertical borders. On desktop and mobile, its top-right three-dot menu contains Mark all as read when unread events exist, Delete all when history exists, and Notification settings; bulk actions never occupy a separate row. Friends puts Add friends at right, with the incoming-request count; it opens `/friends?view=requests`, a separate mobile view containing incoming/sent requests and Add by email, with Back to friends at left. Browser history, refresh and direct links retain that view. Desktop keeps the friends sidebar; tablet keeps the disclosure above the list. Browser theme colours follow the selected appearance, with the platform's default installed-iOS status bar. Bottom-navigation safe-area spacing is bounded to 8–22px so launch-time inset changes cannot double its height.

- Prefer “Feedback”, “Review link”, “Copy text”, “Download”, and “Account” to metaphors or explanatory paragraphs. A little voice belongs in the entry/empty state, not every label.
- No generic success/information notices or prompts. Prefer visible state changes and feedback attached to the action's control. A disconnected connection already says “Not connected”; do not repeat it in a banner or toast. Keep actionable errors beside their controls and dialogs for real decisions or necessary confirmations, not redundant announcements.
- Do not add “Unpublished preview”, “Appearance approximates…”, “Copying text doesn't attach…”, or similar defensive captions. Fix the design that made the explanation necessary.
- Keep actionable errors, save/conflict state, destructive confirmations, and security consequences. Do not add link-ready notices or a separate review-link panel. Older feedback carries a quiet “Earlier feedback” indicator, not a version number or history control. Reviewer composition precedes existing feedback; general feedback is the default, with clickable posts and selected-text quotes as optional focus. Ask guests for a name only when sending. Minimal copy must never disguise data loss.
- Use labelled controls, visible keyboard focus, accessible tab semantics, and comfortable touch targets (40–44px). Never put essential actions behind hover alone. Respect reduced motion.

## Responsive verification

Agents lives in Settings at `/settings?tab=agents`, with a plug icon in the settings navigation,
not the application rail. A compact connection card sits above the list on desktop and mobile,
with brief instructions and a single-line MCP address with an inset copy icon on the right.
Compact rows show the app-provided name and last use, with permissions and disconnect in an overflow
menu at every width. No placeholder agent avatars or disconnected rows.
The copied tick returns to the copy icon after 2.5 seconds.
Permissions open in a shared Dialog on desktop and a separate mobile view at `/settings?tab=agents&edit=<id>`;
permissions are grouped into Drafting, Feedback, Sharing, and AI and X tools, with mixed-state
whole-group checkboxes in every header, including groups with one capability. Groups start collapsed
and expand independently; their headers retain selection counts and whole-group controls.
Sharing separates managing bearer review links from sharing with specific accepted friends.
Collapsing never changes selected permissions or omits them from submission. Attachments are bundled
with draft/review access; friendship and notification management are not agent permissions.
Selecting new authority changes Save changes to Add permissions. The pending request stays attached
to the editor with agent-side approval instructions and a Cancel added permissions action. OAuth
updates an explicitly identified existing connection, keeping its expiry; no delete/re-add step.
Client support for reauthorization varies. Disconnect
uses ConfirmDialog and removes the row. Use last-used timestamps rather than an online dot. OAuth
consent shows the connection destination and an account card with photo, name and handle, defaults
only read permissions on, and keeps each
requested capability independently selectable. Never represent the registration name as verified
agent identity.

Consent and connection editing offer 30 days, 90 days, 1 year and Until disconnected. Consent
defaults to 90 days; editing defaults to Keep current expiry so changing permissions does not
silently renew access. Expired connections cannot extend themselves. The editor saves permissions
and expiry together with Save changes (or Add permissions when new access is selected). Keep the Agents heading/card gap at 16px and the inset copy
action vertically aligned with its 44px address field.

Check login/join, empty and populated drafts, inline editing, media, sharing, settings, guest feedback, failures, and older feedback. Desktop feedback sits beside the post; below 900px it follows it. Mobile retains editing, uploads, post removal, review, feedback focus, copying, and downloads. Check at 390px and a narrower 320px; no horizontal scrolling or tiny replacement controls. Inspect actual rendered screenshots and exercise keyboard and touch interactions, not just CSS breakpoints. See root guidance for required checks.
